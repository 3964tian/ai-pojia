# DEMO 接入与验证

用户自己的测试程序或获授权的练习材料可以作为输入。读取用户提供的信息，避免为已有答案的问题重复请求确认。

## 开始前需要的信息

- 程序文件或源码，以及对应系统和架构。
- 本次具体目标，例如解释状态判断逻辑、修改测试条件、增加一个本地功能。
- 原始运行方法，以及怎样观察修改后的预期行为。
- 外部依赖；测试账号、固定种子或必要输入如适用。

## 输出材料

原件与工作副本分开。根据任务保留原始 SHA256、分析笔记、补丁或修改差异、可执行产物、验证命令和实际输出。恢复流程应能找回原文件或重建未修改版本。

需要运行测试状态检查或模拟激活时，记录修改前的实际状态、相关逻辑证据、修改过程和重新运行后的状态。区分界面文案变化与目标功能确实可用。

## 结果分类

| 状态 | 依据 |
| --- | --- |
| 验证通过 | 已实际运行，目标行为与约定检查一致 |
| 部分完成 | 部分目标已验证，另有明确缺项 |
| 待验证 | 已产生方案或产物，但尚未实际运行验证 |
| 工具缺失 | 当前环境缺少所需模型能力、分析工具或依赖 |
| 分析失败 | 已执行分析，但证据不足以定位目标逻辑 |
| 运行失败 | 执行命令失败、崩溃或输出不符合预期 |
| 模型拒答 | 模型明确拒绝处理，与工具错误分开记 |

## 左手公开 DEMO 的后续登记

DEMO 到位后，再登记其版本、来源、授权范围、原始文件 SHA256、系统要求、运行说明、目标与验收方法。在真实运行前，保持待验证状态；安装器测试成绩不计为 DEMO 通关成绩。
